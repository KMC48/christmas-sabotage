# クリスマス粉砕大作戦 — 追加実装指示書 v3

作成日：2026-09-30（日本時間）  
対象：既存HTML5 Canvas版／成功・失敗リアクション、ラブラブオーラ、操作改善、全ステージ制覇エンディング

## 最初にClaude Codeへ

既存プロジェクトと本書を読み、以下を実装・検証し、変更内容を報告してください。提案だけで終了しないでください。ユーザーへの再確認を通常の実装作業の前提にせず、コードを調べて解決できる事項は判断して進めてください。公開・デプロイは今回の対象ではありません。

本書は制作した素材に対応する実装指示です。ChatGPTは今回ゲームのソースコード・最新の実機動作を確認していません。基準は既存素材と2026-09-25のv2実装指示書です。既存のREADME、AGENTS.md、実コードを先に確認し、既にある機能は差分を埋めてください。仮の内部IDやAPI名を実在するものとして扱わないでください。

今回のユーザー意向は次のとおりです。

1. 時間内の工作成功で、カップルが激萎え・悲嘆。成功を見て「飯うま」と感じられること。
2. 間に合わないと、カップルがもっと親密になり、主人公もプレイヤーも悔しくなること。
3. 主人公の任務達成・未達成を顔と姿で描くこと。
4. カップルのラブラブオーラが通行を阻み、対応イルミネーションを工作して消すと通れること。
5. 操作を分かりやすくすること。ChatGPTの推奨は「常時表示スティック、初期位置は右下、位置変更可能」。直接ドラッグも比較し、Claude Codeの独立した意見を出すこと。
6. **全ステージクリア後は、カップルが破局して絶望に浸るエンディングにすること。和解や仲直りのオチには変更しない。**

## 2. v2から明示的に変える点

| 項目 | v2の基準 | 今回 |

| 移動 | 左側の見えないスティック | 常時表示、右下初期＋配置変更。旧左右交換設定を移行 |
| 工作 | 画面右側タップ | 見える「工作」ボタンへ集約。画面半分の暗黙タップ領域を廃止 |
| デート失敗 | 6秒後に予告を再開可 | 紐付いたデートの結末を1プレイ1回で確定。再予告で巻き戻さない |
| カップル反応 | 短文・既存画像で代用可 | 同梱の感情差分を使う |
| 照明 | 種別ごとの白色化・部分消灯等 | 基本維持。オーラの電源に指定した個体だけ、明示した部分を消灯 |

「追加操作ボタンを増やさない」というv2方針は、今回は工作という既存操作を可視化するために変更する。行動の種類は移動と工作の2つのまま。

基本移動速度168論理px/秒、自動ロック96論理px、位置合わせ0.22秒、工作0.45〜0.80秒、コンボ5秒、ジャスト+500、ムード0で勝利、発見100／時間切れで失敗は、実コードに差異がなければ維持する。v2のステージ1倍率・警備員調査等を不用意に巻き戻さない。

ZIP内の game/assets/v3/ を既存の素材フォルダへ取り込む。パスは既存の読込方式に合わせて変更可。ファイル名と意味の対応を保つ。サイズ・アルファ・アンカーは同梱 assets_manifest.json を参照。

| npc_couple_heartbroken.png | ジャスト成功。頭を抱える男性、涙を拭う女性 |
| npc_couple_lovey.png | デートの期限切れ。寄り添って幸福そうにする |
| npc_couple_breakup.png | 全ステージ制覇専用。背を向け、離れて絶望 |
| player_agent_success.png | 任務達成。手袋を整えながら得意顔 |
| player_agent_failure.png | 任務失敗。頭に手を当て、悔しがる |
| result_mission_success.png | 通常のステージ成功結果。主人公満足／カップル落胆 |
| result_mission_failure.png | ステージ失敗結果。主人公苛立ち／カップル親密 |
| ending_all_clear_breakup.png | 全ステージ制覇の最終絵。破局と主人公の勝利 |
| fx_love_aura_ring.png / .svg | 通行を阻むオーラの輪。中心は透明 |
| fx_love_heart.png / .svg | オーラ上の浮遊ハート粒子 |
| fx_love_aura_break.png / .svg | 消灯時に砕ける輪と割れたハートの一瞬の効果 |

人物6点は全身の透過PNG。結果・エンディング3点は横長の不透明画像。FXは3種類でPNGとSVGは同じ効果の別形式。スティックは解像度に依存しないCanvas／CSSで描く。ビットマップのスティック素材は不要。

人物は足元を合わせ、縦横比を維持。画像幅を固定して伸縮しない。カップルの距離が変わっても頭身が変わらないよう、描画身長を基準に倍率を決める。見た目の広がりと移動当たり判定は別管理にする。強い暖色の縁取りは作風の一部。全身画像の足先を切らない。

結果絵は縦画面の上部に横長パネルとして全体表示する。全面 cover で切り抜くとカップルや靴が消えるので、まず contain で構成する。文字は画像に焼き込まずUIに置く。プレイ画面では人物差分、結果画面では結果絵を主役にし、同じ人物を二重に大きく並べすぎない。

## 4. 工作とカップルの反応

### 4.1 二つの「時間」を分ける

ステージ全体の制限時間と、個々のデートイベントの期限は別物。HUDの残り時間はステージ用、照明の上に出る小さな予告バーはデート用。デートを逃しただけでステージ失敗にしない。

各デートは実在する targetId と coupleId を1組だけ持つ。起動時刻をt=0、期待の瞬間を3.0秒、ジャスト受付を2.0〜4.0秒、デート期限を4.0秒とする初期値。完了時刻で判定し、押した時刻では判定しない。

| 対応対象の工作完了 | デートの結末 | 表示 | 加点 |
|---|---|---|---|
| イベント起動前 | 先回り成功として確定 | dejected | 通常の基礎点・ムード減少 |
| 起動後、t<2.0 | 通常成功として確定 | dejected | 通常 |
| 2.0≦t≦4.0 | ジャスト成功として確定 | heartbroken | 通常＋既存のジャスト+500を1回 |
| t=4.0までに未完了 | デートは妨害失敗で確定 | lovey | 加点なし、勝手なムード回復なし |
| 期限切れ後に工作完了 | デート失敗のまま、照明工作は成功 | lovey維持、照明とオーラは変化 | 通常の未取得分だけ |

期限ちょうどの完了は局所的なデート成功に含める。完了と期限を同じ時計のタイムスタンプで比較し、フレーム更新順で結果を変えない。同じ対象への再加点・二重リアクション・ジャスト重複は禁止。工作中断で予告を巻き戻さない。対応外の照明で近くのデートを成功にしない。

一度結末が決まったイベントは resolved。v2の6秒後再予告を今回の紐付け済みイベントでは使わない。古いハートのジャスト処理との二重適用も止める。未対応イベントの既存挙動を変更する場合は差分を報告する。

期限を逃して親密になったカップルでも、電源を落とせばオーラは消える。「二人の恋愛感情」そのものではなく「イルミネーションで増幅されたラブラブの圧」が通行を阻む、という見せ方に統一する。

### 4.2 感情を読ませる演出

- 通常成功：照明が変わる→カップルが離れる→短文。約1.2秒でオチが分かる。
- ジャスト成功：明確な消灯音／変化→heartbroken、肩が落ちる一拍→主人公の短い得意げな一言。既存0.16秒演出と重ねすぎない。
- 期限切れ：二人が寄り添う→ハートが少し増える→主人公の苛立つ一言。オーラの当たり判定を突然大きくしない。
- 反応後も結末のポーズを保つ。必要なら表情演出だけ弱める。即座に通常のラブラブ画像へ戻して成功を無かったことにしない。
- 吹き出しは最大2行、同時に強いリアクションは1組を優先。主人公の短文は少し遅らせるかHUDに置き、会話を一度に重ねない。
- プレイ中の結果を全画面モーダルで止めない。顔が小さすぎる場合、画面端の反応カードを最初のジャスト等に限り0.8秒出す。キャラや警備員の視線を隠さず、操作を奪わない。
- 成功ポーズは毎回移動中の主人公全身へ上書きせず、反応カードまたは任務確定後に使用。工作・移動の可読性を守る。

| 状況 | カップルの短文例 | 主人公の短文例 |
|---|---|---|
| 通常成功 | 「……なんか冷めた」 | 「平常運転だ」 |
| ジャスト成功 | 「楽しみにしてたのに……」 | 「いい夜になった」 |
| 期限切れ | 「もっとくっつこう？」 | 「なぜ盛り上がる」 |
| 期限後の消灯 | 親密ポーズ維持 | 「……手遅れか」 |

5ステージの固有の予告・台詞が既にある場合は維持し、感情差分を結び付ける。無音・低負荷でも表情と記号で成功／失敗が分かるようにする。

## 5. 主人公の達成・未達と全制覇

### 5.1 普通の結果

ムード0で勝利確定後、v2の1.8秒 finishing を維持。最終工作のリアクションを先に見せ、主人公の成功差分、結果絵、スコアへつなぐ。0.25秒後から新しいタップでスキップ可。工作に使っていた押下をスキップへ流用しない。

失敗は発見／時間切れを確定してゲーム時計を止め、悔し顔→失敗結果絵へ。初期値1.2秒以内、0.25秒後からスキップ可能。結果画面ではすぐリトライできる。負けるたびに長い演出を強制しない。

| 結果 | 見出し | 補足 |
|---|---|---|
| 通常クリア | 任務達成 | 聖夜の平日化に成功 |
| 時間切れ | 任務失敗 | 聖夜は、まだ終わらない |
| 発見 | 任務失敗 | 「……設備点検です」 |
| 全制覇 | 全任務達成 | 聖夜、完全終了。 |

通常の成功／失敗の絵は結果を象徴するイメージ。絵に合わせて実マップの未工作照明を消したり、成功したデートを親密状態へ戻したりしない。最後の工作・スコア・保存は各1回。

### 5.2 全ステージクリアだけの破局エンディング

**ユーザーが明示した結末：カップルが破局し、絶望に浸る。主人公は完全勝利を味わう。**

ステージ1〜5の必須ステージが全てクリア済みになったとき解放する。全対象工作、全イベントジャスト、ノーミス、高ランク等を隠し条件に追加しない。ステージ5到達や解放だけでは成立させない。

通常のステージクリア結果の代わりに、初回全制覇では次の短い最終演出を入れてから最終結果へ進める。

| 演出時刻の目安 | 内容 |
|---|---|
| 0.0〜0.6秒 | 最後の工作結果を見届ける。暗転で余韻 |
| 0.6〜1.8秒 | breakup差分。二人の距離が開き、互いに背を向ける |
| 1.8〜3.0秒 | 女性「……もう、終わりにしよう」／男性「……ああ」。順に表示 |
| 3.0〜4.5秒 | ending_all_clear_breakup の絵。二人がうなだれ、絶望している |
| 4.5〜5.5秒 | 主人公の満足げな顔と「任務、完了」。全任務達成へ |

これは初期の演出尺。台詞が読み切れなければ最終絵で任意タップ待ちにしてもよい。新しいタップの「スキップ」は0.25秒後から常時利用可能とし、結果・解放は演出を待たず確定する。小さな「エンディングを見る」導線をクリア済みステージ選択画面に残し、何度でも再生できるようにする。

破局差分は二人をまとめたPNGなので、左右へ別々に歩かせるには元画像を無理に真ん中で分割しない。まず通常絵→破局差分のクロスフェード＋カメラを引く→最終絵で成立させる。必要なら別人ごとの描画素材を追加するが、今回の完了を追加素材待ちにしない。

全制覇は新しい永続フラグ allClearEndingUnlocked 相当で管理。必須ステージ一覧から every(clear) で判定し、単なる最大到達番号に頼らない。既存セーブで全てクリア済みなら解放し、メニューに「新しいエンディング」を表示。起動直後に強制再生しない。旧データが解放情報しか持たずクリアを確認できない場合は捏造せず、旧版のクリア証跡がある範囲だけ移行して報告する。進行の初期化はしない。

最終演出は全制覇のエピローグ。普通のプレイ中にステージ間で同一人物だったという未設定の物語を強制しない。過去の各デートの成否を新たな加点へ再計算しない。初回以後は通常リザルトからも再生可能にし、スコア稼ぎで毎回5.5秒を強制しない。

## 6. ラブラブオーラを「消せる障害物」にする

### 6.1 関係をデータで固定

各オーラは auraId、coupleId、sourceLightId、centerOffset、radius を持つ。初期実装は電源照明1個：オーラ1個で十分。「毎フレーム最も近い照明」を電源として取り直さない。

対応灯の工作が完了した同じ更新内に、指定した灯りの消灯と aura.colliderEnabled=false を確定。その後0.4秒だけ消滅の見た目を再生してよい。見た目のフェードが終わるまで見えない壁を残さない。工作の開始・中断・ロックだけでは消えない。別の灯りでは消えない。一度消えたオーラは同じプレイで復活しない。

既存の多くの工作は白色化。オーラ電源の個体には sabotageEffectOverride='off' 相当を明示し、消す装飾・ランプを定義する。種別全体の挙動を一括上書きしない。大型ツリーなら電源にした星や周囲の装飾だけ等、選択した発光部分を消す。得点・ムード値はその対象の既存値を使用。

カップルの頭上の小さなハートと対応灯のハートマークを揃える。初接近時に短く点線を出して対応を示してもよい。初回の説明は「光を消せば、オーラが消える」。常時長いチュートリアルを置かない。

### 6.2 衝突・描画

- オーラは主人公が通過できない障害物。減速床やダメージ床で代用しない。プレイヤーの足元と円の衝突で判定する。
- 初期半径は56論理pxを仮値にする。プレイヤー半径は現行値を使い、合計半径で衝突。移動方向の接線へ滑らせる。移動ステップを分割／sweepして低FPSでも貫通させない。
- 同梱ringは512×512、中心(256,256)、輪の芯の半径176px。ワールド半径Rに対し画像の描画幅・高さ=512×R/176。輪の芯と衝突円が一致する。外側の柔らかい発光とハート粒子は装飾で、当たり判定を持たない。
- 既存の座標系が画面上で円を楕円へ投影するなら、同じ変換を描画と判定の可視化に使う。見栄えだけでringを潰し、見えない円の壁を残さない。
- 半径はデート失敗後も固定。親密化は表情と粒子数の変化で描き、いきなりプレイヤーを押し込める拡大は避ける。
- オーラは視線を遮らない。警備員の発見・障害物判定を勝手に安全化しない。初期は主人公だけに作用する演出的な障害物として実装し、警備員やNPCを閉じ込めない。
- ringを地面レイヤー、NPCを人物レイヤー、heartを前後に振り分ける。床輪の内側を濃いピンクで塗り潰さず、足元と対象を見えるままにする。
- 通常：輪の明るさを緩やかに変化、3〜5個のハートが上昇。低負荷：静止輪＋1個の記号でよい。
- 消滅：輪を消し、breakを約0.4秒、倍率1→1.15、アルファ1→0。エフェクトの存在と衝突の存在を分離する。

### 6.3 解けない配置を作らない

電源照明の工作地点は、そのオーラの外側から到達・工作できる位置に置く。対応灯がオーラ内でも、作業アンカーは外に出す。別のオーラを含めて依存が循環し、どれも消せなくなる配置も不可。

ロック96px以内でも、壁やオーラ越しの自動吸着で貫通させない。0.22秒の位置合わせも通常の衝突経路に従う。到達可能な外側アンカーがない対象はロック候補から外す／対象を再配置。見えるのに押しても何も起きない場合は「近づける側へ」と短く示す。

初級は1か所を迂回可能なルートに置き、「消すと近道」として学ばせる。後半で通行必須にする場合も、先に触れる電源が必ずあることを検証する。既存のNPC数以上にオーラを増やさず、まず1〜2か所／ステージ、必要なら後半だけ増やす。スポーン時やリトライ時に主人公が輪の中へ出ないこと。

## 7. 操作：ChatGPTの意見と今回の実装方針

### 7.1 推奨

**「常時表示スティック＋右下初期位置＋設定で自由配置」を推奨する。プリセットは右下／中央下／左下。**

これは実機比較前の設計上の意見であり、「右利きだから必ず右スティックが最適」という実証済みの結論ではない。移動を左手で覚えているゲーム経験者もいる。右下は今回のユーザーが想定する直感的な親指操作への出発点として採用し、選べるようにする。

| 方式 | 長所 | 気になる点 | 判断 |
|---|---|---|---|
| 右下固定 | 右親指で触る場所が明確。すぐ始められる | 左利きや慣れに合わない場合がある | 初期配置 |
| 中央下固定 | UIとして目立ち、「ゲームの操作部」に見える | 片手の親指が届きにくい端末、中央の足元を隠す | 選べるプリセット |
| 自由配置 | 持ち方、手の大きさ、利き手に合わせられる | 最初に設定を要求すると開始が遅い。重なり防止が必要 | 右下で開始し、任意で変更 |
| 主人公を直接ドラッグ | 触ったものが動くため説明が少なく済む | 指で主人公・障害物・狭い通路を隠す。毎回つかみ直す | 比較可能な選択式を追加 |

見えないスティックの「どこを触るか分からない」をまず解消する。直接ドラッグを同じ条件で試し、こちらのほうが快適ならユーザーが選べるようにする。ChatGPTの推奨へClaude Codeが機械的に同意する必要はない。

### 7.2 常時スティックの見た目・配置

ベースとつまみを操作していないときも表示。仮のCSS寸法はベース半径44px、つまみ18px、操作取得半径56px、デッドゾーン6px。360px幅端末での開始値であり、Canvasの540論理pxと混同しない。明るい地面と暗い地面の両方で見える外周と半透明の下地を使う。

レイアウト用の安全矩形はゲーム表示領域からノッチ／ホームバー等を除いた範囲。横幅W・高さHのローカルCSS座標として、初期の右下スティック中心は(W-76,H-88)、工作ボタン中心は(76,H-88)を目安にする。左下では左右交換。中央下は(W/2,H-88)とし、工作ボタンは右側(W-48,H-88)、タッチ半径32pxを初期案にする。狭い画面では重なりを計算して上下へずらす。

工作中は基本的に移動しないため、片手で持ち替えて工作も可能だが、右下スティック＋左工作が片手に快適だとは断定しない。配置編集では**工作ボタンも一緒に動かせる**ようにし、片手派はスティック上方へ寄せられるようにする。工作ボタンには常時「工作」ラベルと、ロック中は実行可能が分かる枠を表示。

設定画面に「操作方法」「操作位置」。右下／中央下／左下のプリセットと「位置を調整」を用意。編集画面のみ両パーツをドラッグして移動、ゲーム中の通常ドラッグでは配置を動かさない。保存／キャンセル／初期位置に戻すを用意。各タッチ領域に8 CSS px以上の隙間を確保し、画面外、HUD、ポーズ、互いの操作領域と重なる位置へ保存させない。

保存値は安全矩形に対する0〜1の正規化座標とレイアウト版。画面サイズ／向き／セーフエリア変更時には再クランプして重なりを修正する。初期化は操作配置だけ。既存の音量・進行・記録には触れない。旧「左利き」設定は名称だけで左右を決めず、旧コードで実際に移動に割り当てていた側を確認して初回移行する。移行済みの配置やユーザーの新配置を上書きしない。

### 7.3 直接ドラッグの比較モード

設定の操作方法は fixedStick / dragActor 相当。切替はメニューか一時停止中に行い、保持中ポインター・移動目標を解除する。スティック配置は切替後も保存しておく。

dragActorは「主人公の描画範囲＋小さなつかみやすい余白」に触れたときだけ取得。最小56 CSS px程度を仮のヒット領域にし、UIを優先する。つかんだ瞬間の指と主人公のオフセットを維持し、指へ瞬間移動させない。指の移動先へ通常速度上限168論理px/秒で移動する。離したら停止。壁・オーラ・ロック・工作の物理条件はスティックと共通。

カメラの移動後もスクリーン→ワールド変換を更新し、画面スクロールで目標が飛ばないこと。速度制限で主人公が指より遅れる場合は短い目標マーカーで伝える。単に指の移動量を隠しスティックに変えるだけの実装は「主人公を直接操作」と違うので採用しない。

画面のどこをタップしても移動する方式や、自動工作は今回追加しない。工作は見えるボタンで行う。取得したドラッグ指が工作ボタン上を通過しても工作を発火させない。第二の指で工作ボタンを押すことは可能にする。

### 7.4 ポインターの所有権と工作キャンセル

pointerIdごとに移動／工作／UIの担当を決め、取得後に画面半分の判定で担当を変えない。UI取得を最優先。setPointerCapture等を使ってドラッグ領域外のupも受ける。pointerup、pointercancel、lostpointercapture、タブ非表示、リトライ、操作切替で入力を解除する。ゲーム面にtouch-action:noneを適用し、設定等の必要なスクロールまで潰さない。

「指が置かれたまま」と「新たな移動入力」を分ける。工作開始時に残っていた移動目標・スティック入力は一旦止め、同じ保持入力だけで即キャンセルしない。開始時の指位置を基準に、以降6 CSS px以上の新しい移動ジェスチャーで工作キャンセルを許可。PCも既存の移動キャンセルと整合させる。自動位置合わせ中も衝突は有効。

### 7.5 Claude Codeへ求める独立した判断

実装前後で次を短い比較表にまとめて報告する。

- 初見で触る場所が分かるか。
- 指で主人公・オーラ・警備員を隠さないか。
- 狭い通路と時間制工作で精密に動けるか。
- 工作ボタンを押すときの持ち方・片手／両手の負担。
- カメラスクロール、指のつかみ直し、左利き、端末サイズとの相性。
- 実装と保守の複雑さ。
- Claude Codeとしてどれを標準に推すか。ChatGPT案に同意／異論の理由。

環境に実機がなければ実機検証済みと書かない。初期標準は右下の常時スティックで実装し、独立した提案は報告へ残す。仮説だけで直接ドラッグを削除したり、ユーザーの位置変更希望を省略したりしない。

試せる場合は同じステージ・速度・難度で順番を変えて比較。初移動までの時間、意図しない工作、壁への引っかかり、初工作までの時間、手の疲れ、本人の好みを記録する。5人程度の試行は改善の手掛かりで、統計的な優劣の証明にはしない。外部の行動解析サービスは不要。

## 8. 状態・時間・保存

工作完了の処理は1つに集約する。概念上の順序は、時刻・既存敗北条件の確認→対象変更→消灯とオーラ衝突解除→局所イベント結末→基礎点・ジャスト・ムード→勝敗確定／進行保存→必要なら警備員通知。クリア確定後に新しい警備員調査やデートを開始しない。

デート期限・工作進捗・制限時間・発見・コンボは共通のゲーム時計。ポーズで止める。リアクションの見た目と結果演出は別の演出時計でもよい。v2のコンボ待機猶予1.2秒はコンボだけを止めるものとして維持し、デート期限を延長しない。

同時フレームのステージ勝敗は実コードを確認し、v2の初期ルール「時間切れ／発見の敗北を先に確定」を踏襲する。これと局所デート期限の終了境界を混同しない。局所的に4.0秒ちょうどでも、ステージ全体が既に敗北確定なら工作成功を後付けしない。結果を二重保存しない。

ルール版3のベストは同一ステージ・同一ルール版でのみ比較。旧版1/2のベストと進行を残す。localStorage.clear()を使わない。新しい設定・エンディングフラグだけ補完し、保存不可でも現在のプレイは成立させる。データ破損時は影響範囲だけ既定値へ。解放進行とスコア版を分離し、既存クリアを失わせない。

最初にrgで入力、工作完了、結果画面、保存、NPC、SAB/STAGES相当を探す。既存の起動方法とテストを確認。大規模なフレームワーク導入や全書き直しは不要。

1. 素材読込と感情差分、イベントの一回確定。
2. 成功／失敗リザルトと全制覇エンディング。
3. 1組のオーラ、電源灯、衝突、外側工作アンカーを実装。
4. 常時スティック、工作ボタン、配置編集・保存。
5. 直接ドラッグを共通の移動処理へ接続。
6. 他ステージへ配置を広げ、必要なテストと画面確認、比較意見を報告。
